Requests (HTTP requests)

Scraping Rules (MUST FOLLOW):

text
✅ DO THIS:
- Respect robots.txt rules
- Add 2-3 second delay between requests
- Identify yourself in User-Agent header
- Scrape during off-peak hours (2-4 AM)
- Cache data (never re-scrape same page)
- Implement error handling & retry logic
- Log all scraping attempts
- Stop if portal owner requests

❌ DON'T DO THIS:
- Scrape during peak hours
- Rapid-fire requests (DDoS-like)
- Use rotating proxies to hide identity
- Bypass robots.txt
- Scrape personal data (PII)
- Overload their servers

Analyze each portal's HTML structure (use browser DevTools)

Identify CSS selectors for:

Property cards

Property titles

Prices

Contact info

Images

Write parser for each portal (separate function)

Implement retry logic (if page fails, retry after delay)

Schedule daily job (2-4 AM using APScheduler/Cron)

Log results to scraping_logs table

Error handling (skip failed pages, log errors)

PART 5: DEDUPLICATION & DATA CLEANING
The Problem: Same Property, Multiple Portals
Example:

text
Portal 1 (99acres): "Godrej Orchard Estate, Plot 1500sqft, Besa, ₹45L"
Portal 2 (MagicBricks): "Godrej Orchard Estate, 1500sqft Plot, Besa, ₹45L"
Portal 3 (Housing.com): "Godrej Orchard Estate Besa ₹45L Plot"
All 3 = SAME PROPERTY, but data variations

The Solution: Deduplication Algorithm
Match Criteria:

text
IF (area_name == same) AND 
   (price within ±10% tolerance) AND
   (area_size within ±10% tolerance):
   
   → GROUP AS SAME PROPERTY
Merge Logic:

text
1. Keep lowest asking price (best deal for buyer)
2. Combine all images from all sources (3 sources = 15+ photos)
3. Track all sources in "source_portals" array
4. Store original URLs for each source
5. Create 1 unified property record
6. Link to all 3 original listings
Expected Results:

Raw scraped: ~2500 listings

After deduplication: ~500 unique properties

Average per property: 3-4 source listings
