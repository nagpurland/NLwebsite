You are building a full-stack “Nagpur Real Estate Operating System” for a solo founder in India.
This one app must act as: research team, analyst, content engine, CRM, campaign manager, and social/WhatsApp assistant.
Everything must run on Replit (backend, frontend, automations).

0. Tech & Architecture
Backend: Python + Flask (or FastAPI if you prefer).

Frontend: Simple HTML/JS or lightweight React, served by the backend.

Database: SQLite with SQLAlchemy, designed so it can later migrate to Postgres (NO Replit DB).

Scheduling: Replit Agents & Automations / cron-like jobs for periodic tasks (daily).

Secrets: ALL external API keys and tokens must be read from environment variables.

Stub external APIs where needed, but design code so real endpoints can be plugged in later.

1. Nagpur Property Data Engine (Research & Analytics)
1.1 Core tables (SQLAlchemy models)
properties

id (PK)

source (string), source_url (string)

city (string), locality (string), micro_location (string)

property_type (string: plot, flat, villa, commercial, warehouse)

project_name (string), builder_name (string)

bhk (int, nullable), super_area (float), carpet_area (float), area_unit (string)

price_total (float), price_psf (float, nullable), rent (float, nullable)

status (string: active, booked, sold, expired, unknown)

first_seen_at (datetime), last_seen_at (datetime)

amenities (text), remarks (text)

infra_events

id, title, description, locality, event_type (metro, road, MIHAN, govt_scheme, etc.), date, source_url

rules_and_regulations

id, title, body_summary, category (NIT rule, NMC rule, NA, FSI, etc.), effective_date, source_url

scraped_articles

id, title, site_name, locality_tag, topic_tag, summary, source_url, publish_date, scraped_at

raw_html (optional, can be in this table or in a separate raw_html_snapshots linked by FK)

social_articles (for Reddit/X/LinkedIn style public posts, via official APIs later)

id, platform (reddit, x, linkedin, etc.), post_id, text_excerpt, topic_tag, locality_tag, url, created_at, sentiment (nullable)

1.2 Scraping & ingestion (structure)
Implement placeholder scraping functions (safe sample sites) but design them to match this pattern:

run_all_scrapers() calls multiple scrapers.

Each scraper normalizes data into properties, infra_events, rules_and_regulations, scraped_articles.

Respect robots.txt: add comments and structure so that in real deployment we only scrape sites that allow it.

For properties:

On first encounter, insert with first_seen_at = now.

On subsequent encounters, update fields and last_seen_at = now.

If a property is missing from sources for N successive runs (configurable), mark status = "booked" or "sold" instead of deleting.

1.3 Analytics & undervalued detection
Implement functions and endpoints to compute, by locality and property_type:

average and median price_psf

number of active properties

rental yield estimate where rent is available (annual rent / price_total)

For undervalued properties:

For each locality + property_type, compute average price_psf.

Mark properties at least 15–20% below this average as is_undervalued = True (add a boolean column).

1.4 Analytics dashboard
/dashboard/analytics – show tables of locality-level metrics and simple charts (can be plain HTML tables).

/dashboard/undervalued – list undervalued properties with filters (locality, type, budget range).

1.5 Daily automation
A daily scheduled job that:

Runs run_all_scrapers().

Updates analytics and undervalued flags.

Triggers reporting + notifications (see section 3).

Web intelligence dashboard

3. Daily Reports, Notifications & Blog Generator (Analyst + Content)
3.1 Daily reports table
Create daily_reports:

id, date, generated_at

key_stats_json (JSON) – include price metrics, undervalued counts, top topics/localities, notable infra events

summary_text – short human-readable summary (3–6 sentences)

After analytics and web-intel jobs:

Create or update that day’s daily_reports row.

3.2 Notifications (email, Telegram, Slack)
Implement send_daily_notifications(report_id):

Email: send summary_text + top stats to a configured address using SMTP settings from env.

Telegram: use BOT_TOKEN and CHAT_ID to send a short summary message.

Slack: use webhook URL to post summary into a chosen channel.

Wire this into the daily automation so it runs once per day after the report is built.

3.3 Content ideas & blog generation
Create content_ideas:

id, date_created, source_type (data_change, faq, social_comment, manual), locality, topic, priority, status (idea, drafting, published), notes

Daily:

From daily_reports.key_stats_json and new scraped_articles, auto-create a few content_ideas (even with stub logic).

Blog generator:

blog_posts table:

id, report_id (FK, nullable), title, body, status (draft, published), slug, created_at, updated_at

Page /dashboard/reports:

List last 30 daily_reports with date and summary_text.

Each row has a button “Generate blog from this report”.

Endpoint /reports/<id>/generate-blog:

Fetch report.

Call an LLM API (e.g., OpenAI via key in env) with a prompt to generate an 800–1200 word blog for Nagpur investors/homebuyers based only on the report data.

Save as a new blog_posts draft.

Page /dashboard/blogs/<id>:

Show blog in a textarea editor.

Buttons to “Save changes” and “Mark as published”.

Endpoint /blogs/published returning published blogs as JSON (for future public site).
